Tracks SPEC v1.14, sections 3.2, 3.6, 4.9 and 4.10.

Run-once answers a repeated act from the ledger instead of performing it again. That is right for a write, and wrong for a look taken after one. The reference deployment watched a model edit a file, read it back to check the edit, and get handed the file as it was before the edit. The replay came back bare, so it read as a fresh answer to a fresh ask, and the model asked again, eleven times, until the turn cap ended the run as if it had only run long.

One ledger, four things it now knows:

- A look after a write sees the write.
- A replay says it is a replay.
- A run asking for the same thing over and over is stopped.
- A run that stops without an answer says why, as a code.

## What changed

- A Safe act at a scope the run has since written to is a new act, not a replay. `AgentEffect.AfterWrites` re-keys it from `AgentRun.WritesTo`, which counts what the run performed, so it holds on the text protocol as well as the native one.
- A replayed outcome reaches the Brain whole, followed by a note that the act already ran in this run with the same arguments. From the third ask of the same act the note goes alone, because the answer is already above it. `ToolExchange.Replayed` marks which answers the ledger gave.
- `StandardAgent.IdenticalCallLimit(int)` bounds how many times a run may ask for the same act before it stops as going in circles. The default is 8; values below 2 become 2. Only asks the ledger answered count toward it, so a look the run legitimately repeats after a write never trips it.
- `AgentOutcome.Failure` carries an `AgentFailure` (category, code, message) whenever a run stops without an answer: `cancelled`, `budget_exhausted`, `turns_exhausted` or `going_in_circles`. A caller switches on the code instead of reading the sentence.
- A brain that nothing answered at (a refused connection, a name that resolves to nothing) is reported as unreachable, with a sentence about the address, rather than as a fault to take to support. The native exception stays inside it.

## Upgrading from 2.0.0

Additive. Nothing shipped is removed or renamed, so existing code compiles and runs unchanged. `AgentOutcome.Failure` is null on every run that answered. A run that exhausts its turns keeps the status it had before, and now also carries `turns_exhausted`.

Two behaviours change on purpose. A look after a write now runs the tool again instead of replaying, so a tool that counted on the replay will be called once more. And a run that keeps asking for the same answer now stops at its eighth ask rather than running to its turn cap; set `IdenticalCallLimit` higher if a deployment genuinely needs more.

It is 3.0.0 rather than 2.1.0 because the model shape changed: `AgentFailure`, `AgentOutcome.Failure` and `ToolExchange.Replayed` are new members of shipped models, so segment 1 advances.
