The release built spec-first, because its consumer had already named the seam. Narration
shipped in 1.13.0 and the first production turn showed the cost of an older asymmetry: the
loop's batched door returned the structured outcome and discarded the run's events; the
streamed door yielded the events and lost the outcome. LLooMA 2.0, needing the pending call's
model-minted id, ran batched — and five narration lines landed in one lump with the answer,
twenty-seven seconds in. Every *control* held on both doors; the *capabilities* did not.
SPEC.md v1.10 §4.14 was written first, and this release implements it.

## The third reading

`RunStreamAsync` — on `StandardAgent`, on `IRunManagementService`, and on `IAgent` — returns an
`AgentRunStream`: an enumeration of the run's events that, once it completes, carries the same
`AgentOutcome` the batched door returns — status, result, and the pending effect with the call
id the model minted. One run, two readings; a caller never again chooses between the answer's
structure and the run's story. The implementation is one honest sentence: `RunCoreAsync` has
always computed the outcome on the streamed door, `ProcessPromptStreamAsync` discarded it with
`setOutcome: _ => { }`, and this release stops discarding it.

## A reading, not a path

The loop stays the only copy (§7.6). `LoopParityTests` gains its derived third-door theory:
every scenario the file will ever hold also runs through `RunStreamAsync`, and the streamed
outcome must equal the batched door's — status, result, the pending act's identity — while the
stream holds answer, effects and record-for-record trace parity. Sabotage-verified: making the
new door discard the outcome again fails all fifteen scenarios at once.

## The honest default

`IAgent.RunStreamAsync` ships as a default interface member, so every existing implementation
keeps compiling. The default adapts `StreamPromptAsync` and assumes the run answered — exactly
the assumption `RunAsync`'s default has always documented, and no less accurate. It cannot know
a held act from the events alone, which is the genuine failing test this release was built
against: the default guesses where the loop knows.

## The record

650 tests × net8.0/net10.0, 68/68 conformance vectors — one new, proven able to fail:
`the-streamed-outcome-carries-the-pending-call`, a narrated caller-tool yield through the third
door whose completion must say `AwaitingInput` and name the pending call. Four profiles
certified, zero warnings, 14 API symbols shipped. Tracks **SPEC.md v1.10**, whose §4.14 this
release implements — spec first, build second, for the first time in this repo's history, and
on purpose.
