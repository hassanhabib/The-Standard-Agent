The release where the agent becomes a document. Everything about a Standard agent that is data
can now **arrive** as data — one JSON body from any form, platform, or database row — and the
run it composes is observable in any collector that speaks the open conventions. No mainstream
framework offers either the way this release does, and both land under the same discipline as
everything before them: test-first, zero warnings, every claim certified.

## Agent as data (`FromJson` / `FromJsonFile`)

The entire configurable surface as one JSON document — one key per capability, named exactly as
the builder verbs, camelCased. Brain (text, OpenAI-native, or Anthropic-native), skills,
knowledge, memory, MCP, gate and judge (model- or rule-backed), the contract schema embedded as
real JSON, constitution, redaction, turn caps, scoped allow-lists, permission modes, risk
levels, approval names, trace, audit, telemetry, sessions, effect ledger, screening, budgets,
usage, resilience, compensation.

The rules carry the framework's honesty into configuration:

- **An unknown key refuses to compose, with the key named.** A form that typos `buget` must not
  get an unbounded agent that looks configured — the failure mode of configuration is never
  silence. Wrong-shaped values refuse the same way, and enum-valued keys name what they accept.
- **Tools stay code, because they are code** — except MCP, where a tool is a URL, which is
  data. Delegates and broker instances stay code too, and code chains after data:
  `StandardAgent.FromJson(formBody).Tool(new CalculatorTool())`.
- **The parity gate**: a test composes a document carrying every data-expressible key, so a
  builder verb added without a JSON binding fails the build, not a code review.

The Host completes the path: drop an `agent.json` beside `Standard.Agents.Host` (or point
`Agent:Config` at one) and the hosted agent composes entirely from it — form → JSON → file →
a running, gated, budgeted agent behind an authenticated endpoint, no C# anywhere. A document
with no brain still stands, heartbeats, and answers with exactly what to add.

## Telemetry — the fourth utility broker

OpenTelemetry-compatible spans and metrics from the dependency-free core, through the BCL's
`ActivitySource` and `Meter`: a span per run, a span per turn, token usage and outcomes as
metrics, named by the **OTel GenAI semantic conventions** so any collector that understands
agents understands this one. One opt-in line — `.Telemetry("teller-agent")` — free until
something listens, and honest when it does: a capped run records `Working`, a budget or
cancellation stop records `Failed`, never a success the run did not earn; whether usage was
reported or estimated travels with the number. All three verbs (`.Telemetry` / `.UseTelemetry`
/ `.OnTelemetry`), the capability matrix's nineteenth row, and `TierDisciplineTests` now names
telemetry in the utility exemption list — the reviewed path, because spans observe the loop and
steer nothing.

The Host exports it: set `OTEL_EXPORTER_OTLP_ENDPOINT` and traces and metrics leave over OTLP
(OpenTelemetry SDK 1.18.0 — 1.12.0 was rejected by this repository's own vulnerability gate).
And the Host's front door now locks: one `Host:ApiKey` line requires `X-Api-Key` on every agent
route, compared fixed-time on the bytes, with the heartbeat left open for probes.

## The Anthropic Messages API, in the box

`.NativeBrainAnthropic(apiKey, model)` — the second native wire shape on the same
`IGeneratorBrokerV1` seam, zero new dependencies: top-level `system`, `tool_use` and
`tool_result` content blocks with the API's turn alternation honored, reported usage, the
`anthropic-version` pin naming the shape it speaks. Both major native protocols are now one
line each, and the seam — not the wire — stays the contract.
