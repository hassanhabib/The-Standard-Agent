The release where the run gains a voice. An agent that goes silent for eight seconds while it
searches, judges and revises feels broken — and every consumer was left to fake progress prose
from machine-voiced `Status` strings, guessing at meaning the framework had and they did not.
Narration closes that, the only way this framework closes anything: as a typed channel with a
guardian in front of it.

## A fifth event kind, between the draft and the answer

`AgentStreamEventType.Narration` carries user-voiced progress prose — "Let me check the
calculator…" — distinct from `Status` (machine-voiced lifecycle) and from `Thinking` (unvetted
draft). The stream's ladder of claim strength now reads draft → narration → settled answer, and
the old contract holds untouched: filtering a stream to `Response` still equals what the batched
call returns. Narration adds a channel; it moves nothing between channels.

## The model narrates, and the tools are the floor

The text protocol gains one optional verb: at most one `SAY:` line before the choice, peeled
before the first-line rule so the act still runs — and never entering the answer, the
observations, or the session's history. The V1 native contract carries the same prose as
`GenerationResult.Narration`, the SAY line's structured twin. Beneath the model sits the floor:
tools declare `NarrationStarting` / `NarrationObserved` templates (`{tool}` and `{payload}`
slots), voiced when the model said nothing — so the run never goes silent just because the model
was terse. Model prose beats the starting template; the observed template always speaks, after
screening, just before the `Tool` event that carries the data.

## Screened before voiced, on both doors, by construction

Model-authored narration is model output crossing to the user with no Judge and no Contract
between them, so the Gate screens it before it is voiced — unconditionally, not behind the
tool-output flag, which governs model input. A refused narration is withheld from every channel —
not voiced, not echoed as a notice that would hand an injected SAY payload a visible oracle — and
recorded in the decision log as `Narration → WITHHELD`. The run proceeds: narration is
decoration, never the work. And because the loop is the single copy both doors share, a batched
run makes the identical gate calls and writes the identical log lines, discarding only the
events — `LoopParityTests` now holds a narrated scenario to keep it that way. The stream
classifier swallows the SAY line whole rather than streaming it token by token, so no unvetted
prose ever leaks into `Thinking` while the verdict is pending.
