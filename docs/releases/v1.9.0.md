The release where integrations became plural. An agent connects to many tools, many MCP
servers, and many skill sources — and from this release, registering a second one **adds** it,
the way `.Tool(...)` always has, instead of silently unplugging the first. The rule holds in
code and in the JSON document alike.

## Many MCP servers, one seam

`.Mcp(...)` and `.UseMcp(...)` accumulate. The agent asks each server what it offers — the MCP
`tools/list` catalog, new discovery on the `IMcpBroker` seam — and routes every call to the
server whose catalog owns the name. When two servers claim the same name, the **first
registered wins**: deterministic, and the same precedence local tools already have over
external ones. A server that is down at discovery keeps only its own tools unavailable and is
asked again on the next call — its outage never takes the other servers' tools with it, and is
never cached as "has no tools".

**Auth is per server, and entirely optional.** A server with no auth takes one argument. Beyond
that, the bases real servers use: an `apiKey` in a header you can rename, a `bearerToken` for
OAuth access tokens and PATs (the MCP HTTP transport's own scheme), and a
`bearerTokenProvider` delegate for OAuth refresh flows — asked before every request, so the
token is always the current one. Your OAuth client runs the flow; the agent carries the result.
Anything stranger implements `IMcpBroker` and joins through `.UseMcp(...)`.

## Many skill sources, one stream

`.Skills(...)`, `.UseSkills(...)` and `.OnSkills(...)` each add a source — a second folder, the
registry beside local files, a delegate beside both — and the skills concatenate in
registration order, exactly as files concatenate in path order within one folder.

## The document keeps parity

`"skills"` and `"mcp"` accept a single value or an array; each MCP entry is a bare URL (no
auth) or an object carrying its own static credentials. A refresh-flow token is code, not data
— it arrives as a delegate, never through the document. The parity gate holds the array forms
in CI like every other key.

Two capabilities deliberately stay single-slot, and the docs now say why: knowledge and memory,
because merging relevance scores across different rankers and choosing which store a `remember`
writes to are questions a framework must not answer silently.
