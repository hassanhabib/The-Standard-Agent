Tracks SPEC v1.15, section 4.14.1.

The loop has always counted what a run spends. It has to: the budget cannot bound what it does not count, so every model call's tokens were added up, taken from the provider when it reported them and counted locally when it did not. The count stayed inside the loop. Somebody watching a run could read a clock and nothing else, and a local model thinking for four minutes looked exactly like a paid one spending forty thousand tokens until each of them ended.

The count is now on the stream.

## What changed

- After every model call the loop makes for the Brain, the stream carries an event of the new kind `AgentStreamEventType.Usage`.
- Its new `AgentStreamEvent.Usage` is an `AgentUsage` holding the run's usage so far: prompt and completion tokens summed across every call of this run, with `IsEstimated` true when any of those calls was counted locally rather than reported.
- Its `Content` is that total as a decimal number, so a consumer that reads only the text still reads it.
- It is the same count the budget bounds, not a second one.
- A draft the Judge sent back for revision counts, because it was written.
- It is never part of the answer: concatenating the Response events still equals the outcome's result.
- The Host's server-sent events carry it as `event: Usage`, the same way they carry every other kind.

## Also in this release

The resume fix held for 3.0.1.0. When a run is resumed in a new process, the perimeter now counts the writes already recorded in the session's exchanges, not only the writes this process performed. A look at a scope written before the resume therefore runs again, instead of being answered from the ledger with the file as it was before the write.

## Upgrading from 3.0.0

For code that composes the agent through `StandardAgent`, this is additive. Existing code compiles and runs unchanged.

A consumer that switches on `AgentStreamEventType` will now see a sixth kind:

- A `switch` with a default branch that treats an unknown kind as answer text will print the count into the answer. Handle `Usage` or ignore it.
- A consumer that filters for `Response`, as the batched door and the Host already do, is unaffected.

It is 4.0.0 rather than 3.1.0 because the model shape changed: `AgentStreamEventType.Usage` and `AgentStreamEvent.Usage` are new members of shipped models, so segment 1 advances.

## Certification

One new vector in the Enterprise profile: **83**, a run says what it spent.

- It fails on behaviour against 3.0.0, which carries no Usage event, while the 82 before it pass.
- It fails again against a build that reports each call's own figure instead of the running total. Its first reply carries a long narration that is spent and never returns to the prompt, so a per-call figure shrinks.

Full gate: 840 unit tests on net8.0 and net10.0, 83 vectors, Enterprise CERTIFIED, Critical CERTIFIED, 6 evals.
