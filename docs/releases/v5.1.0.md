An agent reaches tools it did not write through MCP, and until this release it could only reach a narrow slice of the servers that exist. `.Mcp(url)` sent plain JSON-RPC posts, so a server built with any of the official MCP SDKs refused it before the first tool was listed: `406 Not Acceptable: Client must accept both application/json and text/event-stream`. And most servers people run locally are not reached by URL at all. They are processes started with `npx`, `uvx`, `dotnet` or `python`, speaking MCP over standard input and output, a transport the framework did not speak.

This release makes the agent a client any MCP server can talk to.

## What changed

- **`.Mcp(url)` speaks Streamable HTTP.** Every request accepts `application/json` and `text/event-stream`. A reply that arrives as an event stream is read past the notifications a server may send ahead of it. The session opens with `initialize` and `notifications/initialized`, once, and every request after carries the `Mcp-Session-Id` the server issued and the `MCP-Protocol-Version` it settled on. A server that ends a session (404) gets a fresh one, and the request is retried once. A server older than the lifecycle, one that answers `initialize` with `-32601`, keeps working exactly as before. HTTP failures surface as the same exception types as before, so they are categorized as they always were.
- **`.McpProcess(command, arguments, environmentVariables, workingDirectory, timeoutSeconds)` starts a server and speaks to it over stdio.** The process starts on the agent's first use of its tools, starts again on the call after it exits, and is stopped with the host. On Windows a bare command resolves through `PATH` and `PATHEXT`, so `npx` finds `npx.cmd`. It accumulates beside `.Mcp(...)` and `.UseMcp(...)`, and the first registered wins a name two servers claim.
- **`StdioMcpBroker`** is the broker underneath: one JSON-RPC message per line, the lifecycle first, stray output and notifications skipped, the server's own `ping` answered. Its second constructor runs over a `TextReader`/`TextWriter` pair you already hold (an in-process server, a socket, a test) and joins through `.UseMcp(...)`.
- **Every page of a catalog.** Both transports follow `tools/list`'s `nextCursor` until the server stops returning one. Before, a server that paged its catalog showed the agent its first page and nothing else.
- **Nothing a tool returns is dropped.** Both transports read every kind of content: text as written, an embedded resource as its text, a resource link as `[resource_link name: uri]`, an image or audio as `[image image/png]`, and a result carried only in `structuredContent` as that JSON. Before, anything but text reached the model as an empty string.
- **The agent document takes a command.** An `mcp` entry may be `{ "command", "arguments", "environmentVariables", "workingDirectory", "timeoutSeconds" }`, or the `args`/`env` words MCP clients' own configuration files use, so a server's published setup pastes in unchanged. `DocumentSchemaJson()` and the Host's `--schema` name the new keys.

## Upgrading from 5.0.0

Code that composes the agent through `StandardAgent` compiles and runs unchanged.

- A server reached with `.Mcp(url)` now receives `initialize` and `notifications/initialized` before its first request. A server that does not implement `initialize` answers `-32601` and is used exactly as before. A server that answers it with any other error now fails discovery with that error instead of being used without a session.
- A document's `mcp` entry that is an object no longer requires `endpointUrl` when it carries `command`. One without either is refused, as before.

It is 5.1.0 rather than 6.0.0 because no shipped model changed shape: `StdioMcpBroker` and `StandardAgent.McpProcess` are new routines, and the JSON-RPC models that changed are internal. Segment 2 advances, and 3/4 reset.

- **Unit tests:** 18 new. 9 in `McpWireContractTests` drive the real HTTP broker against a scripted server. 7 in `StdioMcpWireContractTests` drive the real stdio broker against a scripted in-memory server. 2 start a real stdio server process (`Standard.Agents.Tests.McpServer`, built with the solution): one through `.McpProcess(...)`, one from an agent document.
