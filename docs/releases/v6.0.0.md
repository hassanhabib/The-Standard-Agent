SPEC 1.18: §3.2, §3.7, §4.1, §4.2, §10.

An agent grounded on knowledge could not say where an answer came from. A knowledge source handed the agent passages and nothing else, so an agent that had to credit its sources (a bank's policy assistant, a helpdesk answering from runbooks, a coding agent answering from API references) baked the title into the passage and asked the model to repeat it. Models do not, reliably. A citation the model may or may not write is not a citation.

This release lets a knowledge source say where a passage came from, and lets the agent cite it, as a fact the run knows.

## What changed

- **`KnowledgeResult { Text, Score, Source }`.** A passage, the score its source ranked it by, and a source a reader can follow back: a title, a path, an address. A score is comparable only within one source. An empty source means the origin is unknown, and such a passage is never cited.
- **`ISourcedKnowledgeBroker`** sits beside `IKnowledgeBroker`, which is unchanged. A source implements either. Join one with `.UseKnowledge(broker)`, or write it inline with `.OnSourcedKnowledge(query => ...)`. A plain broker, including the Postgres and SQL Server adapters, keeps working and is lifted to passages with no source.
- **The knowledge folder is citable out of the box.** `.Knowledge(path)` sources each passage by the document's path relative to the folder, with forward slashes on every platform, and scores it with the lexical score it already ranked by.
- **`IKnowledgeService.RetrieveSourcedKnowledgeAsync`** returns the same passages, in the same order, as `RetrieveKnowledgeAsync`, each with its score and source. Both doors share one retrieval, so they can never rank differently.
- **`AgentContext.GroundingSources`.** Recall puts each non-empty source of the knowledge it recalled on the run, once, in the order first recalled. The observations are untouched: the brain is shown exactly the passages it was always shown.
- **`.CiteKnowledge()`.** When a run answers, the agent appends one line per recalled source, `Source: ` and the source, after a blank line. It skips a source the answer already credits. `.CiteKnowledge(prefix: "Reference: ")` rewords the line. Citation happens after the Judge, so the Judge scores the model's words and not the agent's. The batched answer, `RunAsync`, the streamed `Response`, the streamed outcome and the session's record all carry the same cited text.
- **Never on a run that did not answer.** A refusal, a question back, a held act and a failure are not cited. Neither is an answer held to a response schema, because a line after JSON breaks the JSON.
- **Who decides.** What the deployment configured wins, then the request, then off: `.CiteKnowledge()` cites for every caller, `.CiteKnowledge(cite: false)` forbids it for every caller, and an agent that never called it lets each request decide with `PromptRequest.CiteKnowledge`.
- **The agent document takes it.** `"citeKnowledge": true`, `false`, or the prefix, `"citeKnowledge": "Reference: "`. Anything else is refused with the key named. `DocumentSchemaJson()` and the Host's `--schema` name it.
- **The Host's V1 run request carries it.** `POST api/V1/agents/runs` and `api/V1/agents/streams` take `citeKnowledge`, `true`, `false` or `null`, and hand it to the run as `PromptRequest.CiteKnowledge`. A caller across HTTP can ask for citation when the deployment expressed no opinion; what the deployment configured still wins.

## Upgrading from 5.1.0

Code that composes the agent through `StandardAgent` compiles and runs unchanged, and answers byte for byte as before: citation is off unless asked for.

- `IRetrievalOrchestrationService.RetrieveGroundingAsync` returns `IReadOnlyList<KnowledgeResult>` instead of `IReadOnlyList<string>`. Code that implements or calls that interface directly reads `.Text` for the passage.
- `RunManagementService`'s constructor gains two trailing optional parameters, `configuredCiteKnowledge` and `knowledgeCitationPrefix`. Source that constructs it compiles unchanged; a binary compiled against 5.1.0 must be rebuilt.
- A test double of `IKnowledgeService` used under the agent's Data nature answers `RetrieveSourcedKnowledgeAsync`, which is what Recall now asks.
- A caller of `api/V1/agents/runs` or `api/V1/agents/streams` may send one new field, `citeKnowledge`. A caller that leaves it out sees the run it always saw. Code that constructs `AgentRunRequestV1` directly compiles unchanged: `CiteKnowledge` is an init-only property that defaults to `null`.
- An adapter that knows a row's title or URL can implement `ISourcedKnowledgeBroker` to make its passages citable. One that does not need do nothing.

It is 6.0.0 rather than 5.2.0 because the model shape changed: `KnowledgeResult` is new, and `GroundingSources` and `CiteKnowledge` are new members of the shipped `AgentContext` and `PromptRequest`, and `CiteKnowledge` is a new member of the Host's shipped `AgentRunRequestV1`. Segment 1 advances, and 2/3/4 reset.
