No SPEC change.

3.0.0 gave a run that stops without an answer a failure code, so a caller switches on `cancelled`, `budget_exhausted`, `turns_exhausted` or `going_in_circles` instead of reading a sentence. It also gave a run a bound on asking for the same act over and over. Both reached the builder. Neither reached every surface an agent is reached through.

This release closes the two gaps.

## What changed

- **The Host's V1 run response carries `failure`.** `POST api/V1/agents/runs` is documented as answering with everything `AgentOutcome` reports, and it dropped the failure: a caller across HTTP could tell that a run did not answer, and nothing more. The response now carries `failure` as `{ "category", "code", "message" }`, the wire form of `AgentFailure`. It is `null` on every run that answered, asked, refused or is waiting, so a caller that never reads it sees the response it always saw.
- **The agent document can set the going-in-circles bound.** `StandardAgent.IdenticalCallLimit(int)` had no document key, while its sibling `EffectLease` had `effectLeaseSeconds`, so an agent composed from JSON ran with the default of 8 and `"identicalCallLimit"` was refused as an unknown key. It is now a key: a whole number, refused unless positive, with the builder's floor of 2 still applied. `DocumentSchemaJson()` and the Host's `--schema` name it.

## Upgrading from 4.0.0

Code that composes the agent through `StandardAgent` compiles and runs unchanged.

- A caller of `api/V1/agents/runs` sees one new field, `failure`. A JSON reader that ignores unknown fields is unaffected; one that refuses them must accept it.
- Code that constructs `AgentRunResponseV1` directly compiles unchanged: `Failure` is the last positional parameter and defaults to `null`.
- A document that carried `"identicalCallLimit"` was refused before and composes now.

It is 5.0.0 rather than 4.1.0 because the model shape changed: `FailureV1` is new and `Failure` is a new member of the Host's shipped `AgentRunResponseV1`, so segment 1 advances. It follows the precedent of 2.0.0, which added `Exchanges` to `AgentTurnV1` on the same V1 route.

## Certification

Two new unit tests: `ShouldPostRunAndCarryTheFailureAsync` pins the failure crossing the wire, and `ShouldStopARunGoingInCirclesFromJsonAsync` pins the document key by the only path it can pass: five turns would end the run `turns_exhausted`, and the document's limit of three ends it `going_in_circles` first. Each failed before the change it pins. The non-positive document case joins the semantic validation theory.

Full gate: 843 unit tests on net8.0 and net10.0, 83 vectors, Enterprise CERTIFIED, Critical CERTIFIED, 6 evals.
