The release where the agent stopped being only configured and started being asked. One composed
agent now serves many callers, each with their own inference options, under a single rule that is
the perimeter restated: **what is established and hard-configured takes precedence, always.**

## The request, and the resolution

`ProcessPromptAsync(new PromptRequest { ... })` — a prompt carrying its own temperature, max
tokens, seed, stop sequences, response schema, opaque provider passthrough, and caller-executed
tools. The raw request exists at the entry's signature and never travels: precedence — configured
→ request → framework default — resolves once at the top of the run into `ResolvedInference`,
which is what rides the loop. No tier below the entry ever learns that precedence exists, and no
tier can see a value precedence discarded. `StreamPromptAsync(request)` is the streamed twin;
`RunAsync(request)` reports how the run ended, which an exposer cannot do without.

## Hard-configured wins, defaulted does not

"Configured wins" required knowing whether a value *was* configured. `.Brain()`'s temperature and
max tokens are now opt-in, so the host that chose 0.3 is distinguishable from the host that said
nothing — the difference between a rule that works and one that silently reads "defaulted wins".
A configured Contract discards the request's schema outright — never merged — and the trace says
so.

## One schema survives, and it seeds both

The surviving schema reaches the wire as `response_format` *and* the Contract guardian. Plenty of
engines accept a response format and quietly ignore it; here the guardian validates and revises
against the same schema regardless, so constrained decoding is an optimization over a guarantee
the architecture already provides. The state where a model is constrained to one shape and
validated against another is unreachable by construction. And the streamed loop now runs the same
shape check the batched one does — a parity gap this work surfaced and closed.

## The perimeter holds at the wire

`ProviderOptionsJson` carries what the core cannot model — vLLM's template arguments, llama.cpp's
grammar, a provider's thinking options — and nothing else: every core-owned wire key is stripped
at the boundary and refused again at the merge, so no broker in any language can be handed a
passthrough that adds a tool or beats a resolved value. Caller-declared tools are vocabulary,
never capability — a call naming one is a terminal answer addressed to the caller, ending the run
`AwaitingInput` with the call riding the session as its pending effect, the same seam a held
approval rides. A caller tool sharing a configured tool's name is dropped at the boundary: nobody
shadows the deployment's own tool.

## Brokers opt in, nobody moves

`IGeneratorBroker` and `IGeneratorBrokerV1` widen with default-member request-carrying overloads
and `HonorsRequest` — batched and streamed — so the five provider packages compile untouched and
opt in on their own schedule. Both built-ins honor the request, with V0 converged onto the same
`JsonObject` construction V1 documents. Every decorator forwards explicitly, because a decorator
that leaned on the default would silently drop the options before the wire.

## The record

616 tests × net8.0/net10.0, 61/61 conformance vectors — ten new, each proven able to fail by
sabotage: the surviving schema, the guardian seeding, graceful degradation, the streamed twin,
the core-owned-keys strip, the caller-tool trilogy, and the criterion itself — N concurrent
requests with N different temperatures against one composition, every run keeping its own. Four
profiles certified, zero warnings, 112 new API symbols shipped. Tracks **SPEC.md v1.7**, whose
§4.13 states the whole seam normatively.
